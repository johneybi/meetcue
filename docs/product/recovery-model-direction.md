# 공통 시간이 없을 때의 복구 모델

2026-09-12. 사용자 채택 방향. 구현 완료·사용자 효과 검증·포트폴리오 수록 확정과 구분한다.

## 중심 원칙

**계산은 제품이 하고, 사회적 판단은 사람이 한다.**

모두의 응답을 확인해도 현재 조건으로 성립하는 후보가 없을 때, 어떤 명시적 조건이 달라지면 회의가 성립하는지 설명한다. 주최자가 복구 경로를 선택하고 필요한 당사자의 동의를 받은 뒤 확정한다. AI 최적 후보 추천은 중심 기능에 넣지 않는다. 문구 초안·요약 등 보조 기능은 별도 검토이며 구현 결정은 없다.

사용자가 제시한 국내 제품별 포지셔닝은 방향 제안의 맥락이다. 이번 기록에서는 각 제품의 최신 기능을 독립 검증하지 않았다. 경쟁사가 복구 기능을 제공하지 않는다거나 시장에 없는 기능이라는 주장으로 전환하지 않는다.

## 계산의 경계

- ‘미응답’은 불가가 아니다. ‘응답을 더 받으면 성립 여부를 알 수 있음’과 ‘알려진 충돌을 바꿔야 성립함’을 분리한다. 모든 응답을 확인했다는 사례에 미응답을 섞지 않는다.
- 현재 참석 조건을 그대로 적용한다. 선택 참석자의 불참만으로 성립 가능한 후보를 실패로 표시하지 않는다. 전원 참석은 별도 희망일 수 있으나 필수 기준과 섞지 않는다.
- 변경 요청은 당사자가 조정 의향을 밝힌 조건만을 대상으로 한다. 명시적인 변경 불가는 추천 경로에서 제외한다. 일정이 보인다는 이유로 이동 가능하다고 추측하지 않는다.
- 경로에는 필요한 사람, 필요한 동의, 일정 변경 건수, 알려진 제약, 아직 모르는 내용을 표시한다. 한 명이 여러 일정을 바꿀 수도 있으므로 사람 수와 변경 건수를 구분한다.
- ‘동의 1명’이 ‘동의 2명’보다 사회적 비용이 낮다고 단정하지 않는다. 점수·성공 확률·최적 순위로 환산하지 않는다. 날짜·시간을 바꾸는 것이 업무 중요도보다 낫다고 결정하지 않는다.
- 조정 의향은 변경 동의가 아니다. 요청 단계에서도 ‘확정 가능’ 대신 ‘동의하면 성립’을 사용한다. 필요한 동의가 모두 들어오면 주최자가 확정한다.
- 기존 답은 같은 후보와 유효한 조건에 대해서만 재사용한다. 새 시간에 이전 답을 복사하지 않는다. 변경 동의는 요청한 후보에 묶고 다른 후보로 전용하지 않는다.

## 끝까지 구현할 단일 사례

아래는 설계 검토용 가상 사례이며 실제 조율 기록이 아니다. 실제 사례를 확보하면 재구성·대조한다.

6명, 다음 주 1시간, 지훈·수진·민수·서연 필수, 도윤·유나 선택. 모든 사람이 아래 세 후보에 답했다. 현재 성립하는 후보는 없다.

| 후보 | 현재 충돌 | 당사자가 밝힌 조건 | 제품이 설명할 경로 |
| --- | --- | --- | --- |
| 화 14시 | 필수 민수의 기존 일정 1건 | 조정해 볼 의향 있음, 아직 동의하지 않음 | 민수 1명의 일정 변경 동의가 필요 |
| 목 16시 | 필수 수진·서연의 기존 일정 각 1건 | 두 사람 모두 조정 의향 있음, 아직 동의하지 않음 | 2명에게 각각 변경 동의가 필요 |
| 금 10시 | 필수 수진의 외근 | 시간 변경 불가 | 현재 조건으로 복구 불가. 변경 요청 대상으로 삼지 않음 |

각 후보의 나머지 사람은 가능하다고 답했다. 두 경로의 숫자는 관찰된 부담의 객관 점수가 아닌 조건 수다.

### 핵심 분기

1. 주최자는 화요일의 1명 변경과 목요일의 2명 변경을 비교한다. 제품은 숫자만으로 하나를 최적으로 지정하지 않는다.
2. 화요일을 선택해 민수에게 요청한다. 민수가 거절하면 화요일은 닫히며 다른 후보에 대한 답은 유지된다. 같은 거절에 반복 양보를 요청하지 않는다.
3. 목요일로 이동하면 수진·서연의 명시적 동의가 모두 필요하다. 한 명의 수락만으로 확정하지 않는다. 동일 경로의 두 사람에게 함께 확인할 수 있게 하되, 두 후보에 대한 변경 약속을 동시에 추진하지 않는다. 이 운영 방식의 지연 비용은 별도 검토한다.
4. 두 명 모두 동의하면 주최자가 확정한다. 기존 캘린더 일정을 자동으로 옮겼다고 주장하지 않는다.
5. 한 명이 거절하면 그 경로도 닫힌다. 다른 사람의 이미 받은 동의는 기록에 남기되 ‘이 후보로 진행하지 않음’을 알리고, 실제 일정 변경 전에 최종 확정을 기다리도록 한다. 제품 밖에서 이미 실행한 변경을 자동 복구했다고 표현하지 않는다.
6. 남은 경로가 없으면 ‘현재 범위와 조건에서는 성립하지 않음’을 보여준다. 주최자가 범위를 바꾸거나 조율을 종료하도록 한다. 필수 참석자를 몰래 제외하거나 시간을 임의로 줄이지 않는다. 범위를 바꾸면 새 후보에 필요한 답을 다시 받고, 과거 후보의 기록은 유지한다.

## 완료 기준

- 두 후보에 고정된 현재 시안 상태 대신 참석자·후보·응답에서 경로를 도출한다.
- 미응답, 변경 의향, 동의, 거절을 다른 상태로 계산한다.
- 1명 거절 → 2명 동의 경로 → 부분 수락 → 전원 동의 → 주최자 확정이 연결된다.
- 부분 수락 뒤 거절·늦은 응답·요청 취소가 잘못된 확정으로 이어지지 않는다.
- 모든 경로 실패를 정상 결과로 표현하고 새 범위 또는 종료로 연결한다.
- 화면을 늘린 수가 아닌, 위 분기를 이해하고 판단할 수 있는지로 검토한다. 구현 테스트는 사용자 효과의 증거가 아니다.

현재 recovery 시안은 이 목표에 미달한다. 이전 시안은 폐기한 역사로 덮어쓰지 않고, 한 명의 확인만 남은 초기 탐색으로 보존한다.
