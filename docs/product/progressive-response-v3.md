# 후보부터 응답하고, 필요할 때 넓히기

> 시각·인터랙션 후속 개선: [한국 제품 레퍼런스 기반 보강 기록](../research/korean-design-refinement/README.md). 반복 카드가 날짜 중심 목록으로 바뀌었고, 일정 조정 확인은 네이티브 모달/바텀시트로 옮겼다. 응답 범위와 판정 규칙은 동일하다.

2026-09-07 · 채용 과제 회고 이후 제품 개선 · 로컬 구현

이 문서는 이번에 구현한 참석자 응답 흐름의 기준이다. v2.2.1 문서와 충돌하는 ‘처음부터 전체 시간표 응답’ 및 ‘부분 범위 제출 없음’ 규칙을 이 범위에서 대체한다. 회의 성립 판정, 필수 참석자와 최소 인원 조건은 유지한다. 과거 제출물이나 답변 v9에 이 구현이 포함되어 있었다는 뜻은 아니다.

## 설계 판단

처음부터 넓은 시간표를 확인하도록 요구하면 짧은 후보 투표보다 첫 응답의 부담이 커질 수 있다. 반대로 후보 세 개만 고정하면 모두에게 맞는 시간이 없을 때 다시 요청해야 한다. 따라서 최초 입력은 최대 세 후보로 제한하고, 필요하면 같은 화면 흐름에서 전체 범위로 확장하도록 했다. 첫 응답이 더 빨라진다는 효과는 아직 사용자 비교 실험으로 확인하지 않았다.

## 구현한 흐름

1. 참석자는 회의 이름, 요청한 사람, 소요 시간, 마감을 확인한다. 회의 내용은 펼쳐 볼 수 있다.
2. 시간순으로 서로 다른 날짜를 우선하는 최대 세 후보를 제시한다. 같은 날짜가 필요하면 서로 겹치지 않는 후보를 추가한다. 특정 시간에 대한 추가 응답 요청이면 그 시간을 먼저 포함한다. 다른 참석자의 비공개 캘린더로 순위를 매기지 않는다.
3. 각 후보에 ‘가능해요 / 옮겨서 참석 / 어려워요’ 중 하나를 명시적으로 고른다. 예시 캘린더의 겹침은 참고 정보이며, 후보 응답을 미리 선택하지 않는다.
4. 후보 응답만으로 제출할 수 있다. ‘옮겨서 참석’을 선택했다면 기존 일정을 옮겨 참석한다는 의미를 확인한다.
5. 모든 후보가 어려우면 ‘다른 시간 찾아보기’를 주 행동으로 제시한다. ‘이 후보들은 어렵다고 보내기’로 추가 입력 없이 마칠 수도 있다.
6. 전체 시간표를 열면 앞서 고른 응답을 유지한다. 이미 제출한 응답을 수정하는 경우, 남은 시간만 예시 일정으로 채울 수 있다. 직접 선택한 내용은 보존한다. 시간표에서 고친 응답도 처음 후보로 돌아갔을 때 반영된다.
7. 전체 범위를 제출하면 주최자의 가용 범위 안에서 실제 새 후보를 생성하고 결과를 다시 계산한다. 빈 칸을 불가로 저장할 때는 수와 의미를 먼저 확인한다.

## 응답과 미확인의 구분

- 후보 제출은 확인한 후보 ID와 범위를 기록한다. 이 밖의 캘린더 기본값은 공유하지 않는다.
- 한 사람이 ‘제출 완료’여도 다른 후보의 응답은 미확인일 수 있다. 미확인을 불가로 바꾸거나 가능 인원에 더하지 않는다.
- 다른 사람이 전체 범위를 열어 새 후보를 추가해도, 후보만 응답한 사람의 참석을 임의로 추정하지 않는다.
- 최초 공통 후보 ID를 유지해, 범위가 확장되어도 다른 참석자의 첫 질문이 불필요하게 바뀌지 않게 했다. 추가 요청 대상은 우선 포함한다.
- 기존 후보 ID를 보존하므로 선택한 시간의 전후 결과를 이어서 볼 수 있다.

## 화면 디자인

데스크톱에서는 회의 맥락과 응답 작업을 두 열로 나누고, 모바일에서는 맥락을 짧게 접어 위에 둔다. 날짜와 시간을 큰 글자로 구분하고, 선택 완료 표식·선택 테두리·라디오 상태를 함께 사용한다. 색만으로 응답을 구분하지 않는다. 선택 컨트롤은 최소 44px 높이이며, 라디오 키보드 탐색과 화면 전환 시 제목 포커스를 지원한다.

모바일 응답 CTA는 아래에 유지한다. 시연 도구는 헤더에 두어 선택 버튼을 가리지 않게 했다. 전체 시간표의 선택 도구도 세 항목을 한 줄로 배치했다. 주최자 결과에서는 전체 비교표를 기본으로 접고, 선택한 후보와 다음 행동을 먼저 보여준다. 모바일 결과의 날짜와 시간은 줄을 나눠 시간 표현 중간이 끊기지 않게 했다.

주최자의 회의 정보 단계는 회의 이름만 필수다. 회의 설명과 자료는 선택 입력이다.

## 검증과 남은 일

개발 에이전트가 로컬 브라우저에서 확인한 내용이다. 사용자 테스트 결과와 구분한다.

- 후보 선택, 일정 조정 확인, 응답 저장, 편집 시 선택 복원.
- 같은 후보에 실제 응답을 보내고 결과 보드의 pending → ready 변화 및 조정 참석자 표시 확인.
- 모든 후보 불가일 때 확장과 즉시 제출 경로 확인.
- 전체 시간표 왕복 시 선택 보존, 시간표 수정의 후보 반영.
- 저장된 응답을 유지한 채 남은 시간만 채우고 제출, 결과에 새 후보가 추가되는 것 확인.
- 회의 이름만 입력한 상태에서 참석자 단계로 진행.
- 320px·390px·1280px에서 레이아웃 확인. 320px에서 페이지 최소 너비 때문에 생기던 가로 스크롤 수정 후 페이지 폭과 가용 폭 일치 확인. 라디오를 Space·방향키로 선택하는 동작 확인.
- 빌드, 린트, 도메인 테스트 39개 통과. 새 테스트는 공유 범위, 미확인 판정, 재편집, 후보 확장, 요청 대상 포함, 잘못된 입력 거부를 다룬다.

실제 캘린더 연동, 서버 저장, 다중 사용자 동시 접속과 실제 알림 전송은 구현 범위 밖이다. 현재 캘린더는 명시된 예시 데이터다. 다음 검증은 후보 투표와 이 흐름의 첫 제출 시간, 전체 시간표 확장 비율, 응답 의미 오해, 주최자의 확정 판단 정확도를 같은 조건에서 비교하는 것이다. 효과 수치를 관찰 전에 답변에 넣지 않는다.
