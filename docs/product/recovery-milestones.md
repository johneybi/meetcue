## 진행 우선순위 정정 · 2026-09-13

사용자 지시: 화면디자인 우선, 개발 구현은 후순위로 둔다. M1의 기존 완료 표기는 의미·기능 검수에 한정되며 화면디자인 완료가 아니었다. 최초 응답 → 제출 전 확인 → 응답 완료의 세 화면을 먼저 수정했다. [시안과 남은 판단](../design/m1-screens-2026-09-13/README.md)을 리뷰한 뒤 M2의 대표 화면을 정리한다. M3 개발 연결을 선행하지 않는다.

## M1 결정과 의미 표

기존 응답 값을 그대로 재해석하면 저장된 약속을 철회하거나 새 의향을 동의로 승격할 수 있다. 따라서 저장값을 분리하고 기존 데이터는 변환하지 않는다.

| 응답 | 저장값 | 의미 | 확정 인원 |
| --- | --- | --- | --- |
| 가능해요 | available | 일정 변경 없이 참석 가능 | 포함 |
| 조정 검토 가능 | adjustment_intent | 조정을 검토할 의향, 실제 변경 동의 전 | 제외 |
| 어려워요 | unavailable | 이 후보로 참석하기 어려움 | 제외 |
| 이전 옮겨서 참석 | adjustable → 계산상 adjustment_commit | 옛 화면에서 정해지면 옮겨 참석하겠다고 명시한 약속 | 기존 의미대로 포함 |
| 요청 후 변경 동의 | 복구 모델의 요청 ID·후보·당사자별 yes | 해당 요청에만 유효한 명시적 동의 | 해당 경로의 조건으로 사용 |

새 입력은 adjustment_intent만 생성한다. 기존 adjustable은 읽기·편집에서 이전 응답이라고 표시하고, 사용자가 다른 답을 고르기 전까지 보존한다. 새 값과 옛 값이 30분 칸에 섞이면 의향이 남은 전체 후보를 동의 완료로 계산하지 않는다.

필수 조건과 최소 인원이 이미 충족되면 선택 참석자의 의향 때문에 확정을 막지 않는다. 충족되지 않지만 알려진 의향의 동의를 받으면 성립하는 후보는 recovery로 구분한다. 미응답이 필요한 경우 pending, 명시적 불가나 최대 인원 부족은 impossible이다. 의향을 미응답 인원에 포함하지 않는다. 최종 확정 동작도 재계산한다.

일정 상세·건수는 초기 응답의 필수 입력으로 추가하지 않았다. 복구 모델의 상세가 빈 경우 변경 없음으로 추측하지 않고 건수 미확인으로 표시한다. 캘린더에 겹치는 일정이 보이는 것만으로 조정 가능 또는 정보 공유 동의를 추정하지 않는다. 실제 상세 수집 경로는 M2/M3에서 검토한다.

## 근거와 범위

- 빌드·린트·도메인 테스트 63개 통과. 의향/미응답/불가/기존 동의, 선택 참석·최소 인원, 저장 후 재계산, 의향의 확정 차단, 미공유 일정 건수를 검증.
- 브라우저: 개발용 검토 화면의 참석자 응답에서 새 선택지·설명·제출 전 안내·완료 요약 확인. 사용자 저장 회의는 변경하지 않음.
- [캡처](../design/response-meaning-2026-09-13/intent-confirmation.png): 2026-09-13, `/meetcue/design-review.html`의 참석자 응답, 첫 후보 의향+나머지 가능, 기본 데스크톱 뷰포트의 제출 전 안내. 실제 사용성 연구 아님.
- 서비스의 실제 변경 동의 요청은 아직 복구 시안과 별도다. M1은 의미와 확정 안전성의 기반 완료이며 end-to-end 제품 완료가 아니다. 새 상태에 맞춘 대표 화면/진입/요청 동작은 M2/M3 작업이다.
- 사용자 기여: 문제 초점·설계 철학·마일스톤 순서·착수 결정. 에이전트 기여: 기존 의미 충돌 발견, 저장값 분리, 계산·화면·테스트 구현. 포트폴리오 수록 미정.

2026-09-14: 최초 응답의 간격 기준을 확인·완료 화면에 확장했다. [검토 기록](../design/m1-review-receipt-2026-09-14/README.md). M1 화면 시안은 사용자 리뷰 대기이며 다음 디자인 대상은 M2 대표 화면이다.
