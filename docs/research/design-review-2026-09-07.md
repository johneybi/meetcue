# MeetCue 설계 보강 기록

상태: 설계 가설 정리 및 프로토타입 수정. 실제 사용자 비교 검증 전.

이 문서는 2026-09-07 회고 이후의 개선 기록이다. 당시 제출물이나 탈락 이유를 재구성한 문서가 아니다. 당시 지원 답변 후보 v6와 회고용 v8은 수정하지 않았다. v6가 실제 지원 폼과 동일한지는 확인되지 않았다.

## 먼저 다시 쓴 세 가지 답

- **누구의 어떤 수고인가?** 필수·선택 참석자가 섞이고 일부 응답이 남은 회의에서, 주최자가 현재 응답으로 확정해도 되는지 다시 계산하는 수고를 줄이려 한다. 이것이 일정 조율의 가장 큰 병목인지는 확인하지 않았다.
- **무엇을 바꾸는가?** 응답표를 기준 충족 여부와 다음 행동으로 요약한다. 기다릴 필요가 없으면 가능한 다른 시간을 먼저 보여주고, 특정 후보가 필요할 때만 추가 응답을 요청하게 한다.
- **왜 더 단순한 대안보다 나은가?** 아직 일반적인 우위를 주장할 수 없다. 후보가 이미 좁혀져 있으면 소수 후보 투표가 더 간단할 수 있다. 캘린더가 충분히 채워져 있고 후보를 다시 찾는 일이 반복되는 조건에서 범위 입력의 이익이 있는지 비교해야 한다.

## 근거와 가설의 경계

| ------------------------------------ | ------------------------------------------------- | ------------------------------------------- | ----------------------------------------------- |
| 다수 가능과 회의 성립은 다를 수 있다 | 과제의 필수·선택 조건, 결정 모델 예시와 테스트    | 조건 차이를 계산하는 설계를 구현했다        | 주최자가 이 계산을 실제로 어려워하는 빈도·영향  |
| 응답을 모두 기다리지 않아도 된다     | 최소 인원 충족 + 선택 참석자 미응답 상태의 테스트 | 조건 충족 시 확정 가능으로 표시한다         | 사용자가 이 신호를 신뢰하고 올바르게 행동하는가 |
| 캘린더 초안은 입력을 줄인다          | 더미 데이터 자동 입력 동작                        | 비어 있는 칸을 가능 초안으로 채운다         | 실제 캘린더 누락, 검토 비용, 잘못된 가능 응답   |
| 상태를 골라 적용하면 입력이 쉽다     | 반복 클릭을 직접 상태 선택으로 교체               | 같은 칸을 여러 번 눌러 순환시킬 필요가 없다 | 도구 선택을 배우는 비용과 실제 수정 오류        |
| 일정 조정을 참석 약속으로 이해한다   | 명시적 라벨·설명·저장 전 확인 추가                | 의도를 분명하게 전달하도록 수정했다         | 설명 없는 첫 사용에서 같은 의미로 이해하는가    |
| 범위 입력이 후보 투표보다 낫다       | 현재 없음                                         | 특정 조건에서 유리할 것이라는 가설          | 두 방식의 탐색·입력·추가 요청 비용 비교         |

## 대안 선택을 다시 열어둔다

| 대안                          | 유리할 수 있는 조건                                     | 비용·위험                                   | 이번 결정                                           |
| ----------------------------- | ------------------------------------------------------- | ------------------------------------------- | --------------------------------------------------- |
| 후보 3개에 답하기             | 가능한 후보가 이미 좁혀졌고 그중 적절한 시간이 있음     | 처음 고른 후보 밖 시간은 다시 물어야 함     | 비교 기준으로 유지. 열등한 방식이라고 주장하지 않음 |
| 캘린더 초안에서 범위 수정     | 일정이 충분히 기록돼 있고 후보 누락으로 재조율이 반복됨 | 검토 범위, 캘린더에 없는 제약, 연동 전제    | 현재 구현 유지, 일반 우위 주장은 보류               |
| 후보가 안 맞을 때만 범위 확장 | 첫 입력을 짧게 하고 실패 시 탐색 확대가 필요함          | 두 입력 방식의 전환과 기존 응답 보존이 필요 | 비교 후 판단. 이번에 새 생성 모드로 구현하지 않음   |

후보를 빠짐없이 탐색하는 것 자체를 성공 기준으로 삼지 않는다. 적절한 회의 시간 하나를 정하는 데 든 전체 수고와 오류를 비교한다.

## 이번 제품 수정과 이유

1. **불필요한 기다림을 줄일 선택지:** 선택한 후보는 대기 중이어도 확정 가능한 다른 시간이 있으면 날짜·인원과 이동 버튼을 추가 요청 위에 보여준다. 기존 후보를 숨겨 재요청의 필요성을 인위적으로 만들지 않는다.
2. **명시적인 응답 적용:** 참가자 시간표의 순환 클릭을 가능·옮겨서 참석·불가 선택 후 적용 방식으로 바꾼다. PC 드래그, 모바일 탭, 키보드 적용에 같은 선택 상태를 사용한다. 버튼 이름에 날짜도 포함한다.
3. **참석 의사 확인:** ‘옮겨서 참석해요’의 의미를 입력 도구에서 설명하고, 해당 칸이 있으면 저장 전 다시 확인한다. 아직 옮길 수 있을지 모르는 상태는 참석 약속으로 세지 않도록 불가 후 수정 경로를 안내한다. 별도의 ‘조정 가능성 확인 중’ 상태는 추가하지 않았으며, 이 보수적인 선택이 가능한 후보를 과도하게 줄이는지도 검증한다.
4. **신규 참석자 예시 복구:** 신규 참석자에게 남아 있던 숨은 응답 초안을 제거해 캘린더 초기화가 실행되게 한다. 예시 일정은 고정 요일 대신 실제 조율 범위의 앞 세 날짜에 배치해 시연 날짜가 바뀌어도 검토할 일정이 보이게 한다. 실제 캘린더 연결은 아니다.
5. **전후 맥락:** 데모의 응답 후 결과와 확정 바로가기는 같은 대표 후보를 선택한다. 데모 가이드는 장면마다 예시 데이터를 불러온다는 사실을 명시한다. 직접 응답한 내용의 효과는 재요청 후 참가자 화면에서 저장하고 결과로 돌아오는 경로로 확인한다.
6. **읽을 수 있는 설명:** 한 사람에게 ‘수진님 중 1명’이라고 설명하던 문구와, 모바일 대기 상태에서도 ‘확정할 수 있는 이유’라고 나오던 제목을 고친다.

이 수정들은 화면과 코드에서 확인한 문제에 대한 교정이다. 입력 시간이 줄었다거나 사용자가 더 잘 이해한다는 검증 결과가 아니다.

## 다음 판단을 바꿀 조건

- 소수 후보 방식에서 적절한 시간을 충분히 찾고 범위 입력의 수정 부담만 크다면: 후보 중심 시작 또는 범위 축소를 우선 검토한다.
- 캘린더에 없는 외근·집중 시간이 가능으로 남으면: 초안 기본값과 검토 안내를 재설계한다.
- 참석자가 ‘옮겨서 참석’을 잠정 가능으로 이해하면: 현재 저장 확인만으로 충분하다고 보지 않는다. 확인 중과 확약의 분리 또는 후보별 재확인 흐름을 검토한다.
- 상태 요약에서 올바른 선택이 늘지 않으면: 상태 설명을 늘리기 전에 정보 우선순위와 원본 표의 역할부터 검토한다.

## 구현 확인 기록

- 도메인 테스트 34개 통과. 신규 참석자의 숨은 초안 제거와 같은 후보의 대기 → 확정 가능 변화, 기존 확정 가능 대안 보존을 확인했다.
- 로컬 브라우저에서 대기 후보의 대안 시간으로 이동, 캘린더 7개 일정 반영, 마우스와 키보드로 일정 이동 응답 적용, 저장 전 확인 취소·재확인·저장, 같은 대표 후보의 재판정과 최종 확정 완료를 확인했다.
- 390×844 브라우저 뷰포트에서 날짜 전환, 응답 적용, 저장 확인, 하단 대안 이동 버튼을 확인했다. 실제 휴대전화 터치·화면 판독기 검증을 대신하지 않는다.
- 모바일 저장 확인 중 데모 가이드가 버튼을 가리는 문제를 발견해 확인 중에는 가이드를 숨겼다. 대기 화면의 하단 우선 행동도 가능한 다른 시간으로 이동하도록 맞췄다.
- 기존 v6/v8 원본 및 외부 배포는 변경하지 않았다. 기능 시연에서 표시되는 캘린더·요청·알림은 시뮬레이션이다.

이 기록은 구현 점검이며 실제 참가자 관찰 결과가 아니다.
