# 사용자 레퍼런스 적용 · 2026-09-07

[무드 이미지 12장과 해석](../../design/references/2026-09-07/README.md)을 바탕으로 공통 표면과 조작 상태를 정리했다. 기존 서비스의 정보 구조와 판단 로직은 유지했다.

## 화면

- [만들기 · 데스크톱](01-create-desktop.png): 회백색 바탕, 흰 작업 패널, 공통 선택 상태와 주요 버튼.
- [홈 · 모바일](02-home-mobile.png), [홈 · 데스크톱](03-home-desktop.png): 요약과 진행 중인 회의의 패널 깊이를 맞추고 보조 정보는 간결한 목록으로 유지.
- [회의 결과](04-results-desktop.png): 선택 후보는 파란 면과 선, 결정할 내용은 흰 패널 안에 배치.
- [참석자 응답 · 모바일](05-response-mobile.png): 날짜별 응답 카드, 선택 표시, 진행 수.
- [만들기 · 모바일](06-create-mobile.png): 화면 폭에 맞는 패널, 날짜 입력, 2열 시간 선택, 하단 버튼 여백.

## 검증

- 브라우저에서 만들기 → 참석자 → 시간 범위, 홈 → 회의 결과 → 초대 현황 → 참석자 응답 → 로고로 홈 이동을 확인했다.
- 시간 길이·참석 방식의 선택/미선택, 주요 버튼 활성/비활성, 응답 라디오 선택에 따른 진행 수 변화를 확인했다. 응답은 제출하지 않았다.
- 실제 계산 스타일에서 주요 버튼과 시간 선택지가 공통 그라데이션·그림자 토큰을 사용함을 확인했다.
- 390px에서 홈·만들기·응답을 시각 확인했다. 320px에서도 만들기·응답 페이지의 가로 넘침이 없었다. 모바일은 기존 전체 폭 패널의 음수 여백을 제거하고 하단 버튼에 좌우 20px 여백을 복원했다.
- 주요 CTA는 흰 글자 대비가 밝은 끝 `#2471e3`에서 4.62:1, 어두운 끝 `#1c64d8`에서 5.44:1이다. 선택 항목의 글자 `#185bc3`와 바탕 `#e9f2ff`는 5.60:1이다. 페이지 전체의 접근성 적합성을 인증한 것은 아니다.
- 공통 버튼 눌림 160ms, 기존 응답 선택 표시 이동 180ms를 사용한다. 모션 감소 환경의 CSS 대체 동작을 유지했다.
- `npm run build`, `npm run lint`, `npm run test:domain`(44개), `git diff --check` 통과.

입력 데이터가 있는 로컬 프로토타입을 사용한 시각 검증이다. 외부 메시지 전송이나 실제 일정 확정은 이번 검증에서 수행하지 않았다.
