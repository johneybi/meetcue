## D-001 · 무드보드를 참고하되 화면 구조의 의무로 만들지 않기

- 작업 맥락: 2026-09-07 이후, 사후 디자인 개선. 기록일 2026-09-12.
- 출처: 사용자는 문서를 무조건 따를 규칙으로 보지 않으며 무드·스타일을 참고하자고 설명했다. [이미지 12장과 당시 해석](../design/references/2026-09-07/README.md).
- 대안: 평면적인 업무 도구 / 레퍼런스의 강한 입체 표현 / 밝은 면과 얕은 입체감을 정보 위계에 맞춰 적용.
- 판단: 부드러운 표면과 명확한 선택 표시를 참고하되 장식용 차트·유리 프레임·사진 배경까지 이식하지 않는 방향이 기존 기록에 남아 있다. ‘그라데이션 전면 금지’로 요약하지 않는다.
- 산출물: [적용 및 검증 기록](../research/reference-mood/README.md). 원본 이미지도 보존되어 있다.
- 불확실성: 사용자 취향과 설계 일관성에 대한 판단이며 사용성 개선 효과를 입증한 것은 아니다.
- 수록 검토: 모방한 결과보다 무드의 어떤 속성을 어떤 기능에 배분했는지를 보여줄 수 있다. 원본 출처·공개 사용 범위는 미확인.

## D-002 · 배경이 비활성처럼 보이고 카드끼리 재질이 달랐던 안

- 작업 맥락: 사후 개선의 여러 차례 시각 피드백. 정확한 개별 발언 날짜는 미상. 기록일 2026-09-12.
- 사용자 피드백: 상단 회색이 disabled처럼 보임, 배경이 dimmed처럼 보여 카드만 부각됨, 주 카드와 보조 카드의 디자인 차이가 큼.
- 대안: 어두운 바탕으로 흰 카드 강조 / 밝은 바탕과 일관된 표면, 배치·타입·여백으로 위계 확보.
- 판단: [표면 역할 기록](../research/surface-intent/README.md)에는 상단이 밝고 아래로 옅은 회색이 되는 후속 수정과 일반 패널 그림자 축소가 기록되어 있다. 다른 시점의 모든 어두운 안이 같은 변경으로 해결됐다고 단정하지 않는다.
- 전후 자료: 위 문서의 캡처와 [2026-09-09 보존 화면](../research/visual-direction-2026-09-09/01-current.png), [리듬 검토 보존 화면](../research/rhythm-2026-09-10/result.png). 뒤 두 이미지는 대응 설명이 없는 단독 보존 자료이며 정확한 버전·동일 조건 전후 비교는 미확인.
- 검증 한계: 기존 문서의 브라우저 확인은 시각·기능 확인이다. 선호도나 가독성 향상의 측정 결과는 없다.
- 수록 검토: ‘더 예뻐짐’보다 상태처럼 읽히는 배경과 과도한 카드 대비를 수정한 판단으로 설명할 가치가 있다.

## D-003 · 입력을 돕던 도구들이 입력보다 앞서 보이게 된 문제

- 작업 맥락: 2026-09-10 전후, 사후 시간 선택 개선. 기록일 2026-09-12.
- 사용자 피드백: 추가/제외 active 구분이 약함, 시간 입력 마찰, 색·컴포넌트·화면 복잡도, 중복·애매한 정보와 타이포그래피.
- 이전 안: 상시 모드 선택, 직접 입력 폼, 프리셋·범례·보조 도구가 함께 보이는 구성.
- 대체 안: 클릭 선택/해제와 시작 칸 기준 드래그, 별도 직접 입력 창, 보조 도구 정리, 공통 색·타입 위계.
- 근거와 전후: [단순화 기록 및 이미지](../design/time-simplification-2026-09-10/review.md), [앞선 입력 개선 기록](../design/time-clarity-2026-09-10/review.md), [기능 확인 기록](../design/time-entry-2026-09-10.md).
- 판단: 기능 개수가 늘어도 완료가 쉬워지는 것은 아니라는 설계상 반성. 기존 기록에는 상시 전역 모드 제거가 보고되어 있다. ‘제외 편집 기능 전체 폐기’로 기록하지 않는다.
- 미측정: 실제 사용자의 입력 시간·오류·키보드/터치별 완료율.
- 수록 검토: 전후와 시행착오가 남아 있어 유력한 소재. 기능 확인만으로 사용성 향상을 주장할 수 없다.

## D-004 · 처음부터 전체 시간표를 받기 vs 후보부터 받기

- 작업 맥락: 2026-09-07 후보 우선 응답 구현 기록. 기록일 2026-09-12.
- 문제 가설: 넓은 시간표는 첫 응답 부담이 크지만 후보 고정은 합의 실패 시 재질문을 만든다.
- 선택: 최대 세 후보에 먼저 답하고 필요하면 범위를 확장. [설계·구현·검증 기록](../product/progressive-response-v3.md).
- 비용: 새 후보에 다른 사람의 답은 미확인이다. 재질문과 추가 입력 비용이 생긴다. 시간순·날짜 분산의 세 후보가 실제 참석 가능성이 높은 추천이라는 뜻은 아니다.
- 비교에서 보류한 결론: 전체 범위 입력이 나쁘다거나 후보 우선이 더 빠르다는 효과 판단. 첫 응답과 조율 전체의 비용을 분리해 봐야 한다.
- 재검토 조건: 최초 후보가 모두 안 맞는 상황에서 재질문까지 합한 비용이 커지면 후보 선정·확장 방식 수정.
- 수록 검토: 부분 응답의 불확실성을 보존하는 설계를 설명할 수 있다. 실제 시간 절감이나 경쟁 우위는 미검증.

## D-005 · ‘분석할 수 있음’에서 ‘실제로 조율 수고를 줄임’으로

- 사건·기록일: 2026-09-12, 사후 경쟁력 검토와 공개 사례 조사.
- 출처: 사용자가 경쟁력을 비판적으로 검토해 달라고 요청. [경쟁력 검토](../research/competitiveness-2026-09-12/review.md), [공개 사례 조사](../research/public-scheduling-cases-2026-09-12.md).
- 기존 초점의 위험: 복잡한 조건을 판정하고 보기 좋게 보여주는 능력이 사용자에게 가장 중요한 문제인지 확인되지 않았다.
- 제안된 관점: 입력·응답 대기·추가 확인·확정까지 이어지는 조율 수고를 살핀다. 미확인을 참석으로 계산하지 않는 모델은 유지할 가치가 있다.
- 근거의 경계: 공개 자기보고에서 미응답·캘린더 불일치·조정 동의가 드러났다. 빈도 조사, 직접 인터뷰, MeetCue 효과 검증은 아니다.
- 대안: 홈·알림·대시보드 확장보다 입력과 확정의 핵심 장면을 먼저 비교한다. 이는 권고이며 새 구현 완료 기록이 아니다.
- 수록 검토: 증거를 보고 문제 정의를 수정하는 과정. 지원서 탈락 원인을 밝혀냈다는 서사로 쓰지 않는다.

## D-006 · ‘안 물어볼 시간’은 정말 없어도 되는가

- 사건·기록일: 최근 사용자 질문과 2026-09-12 공개 조사 후 재검토. 미구현 제안.
- 문제: 추가/제외를 이해하는 부담과 긴 범위를 직접 채우는 부담 중 무엇이 큰가?
- 대안: 추가만 제공 / 두 모드를 상시 노출 / 동일한 최종 범위를 만들되 전체에서 제외하는 보조 편집 제공.
- 현재 제안: 대부분 열려 있는 범위는 제외가, 일부만 열려 있는 범위는 추가가 유리할 수 있다. 주최자의 ‘질문할 범위’와 참석자의 ‘참석 가능 범위’를 구분한다.
- 근거: [공개 조사 B1·B2](../research/public-scheduling-cases-2026-09-12.md)의 날짜별 범위·긴 모바일 입력 피드백. 제외 UI 자체의 효과를 증명한 자료는 아니다.
- 미결정: 기본값, 노출 위치, 명칭, 실수 복구 방식. ‘이 기능이 확실히 필요 없다’고 결론 내리지 않는다.
- 재검토 조건: 속도가 빨라져도 불가능한 시간을 가능으로 저장하는 오류가 늘면 설계를 수정한다.
- 수록 검토: 단순화와 다양한 사용자 상황 사이의 절충. 비교 관찰 결과를 보강해야 한다.

## D-007 · AI의 존재감보다 입력 마찰을 줄이는 데 사용할 것인가

- 사건·기록일: 2026-09-12 대화. 사후 개선 제안, 개발 착수 결정 없음.
- 사용자 맥락: AI 추가가 어색하지 않을지 질문했고 다른 AI 프로젝트도 다뤄봤다고 설명했다. 다른 프로젝트의 구체적 내용은 확인하지 않았다.
- 에이전트 권고: MeetCue까지 AI를 전면에 내세울 필요는 없다. 기본 입력을 먼저 정리하고 복잡한 조건에서 자연어 보조 입력을 비교한다. 사용자가 AI안을 폐기하거나 도입하기로 확정한 것은 아니다.

| 검토안 | 기대 역할 | 우려·보류 이유 |
| --- | --- | --- |
| AI 최적 시간 추천 | 후보 추천 | 명시적 조건 계산보다 나은 점이 불분명하고 참석·동의를 추측할 위험 |
| 일정 조율 챗봇 | 대화로 전체 작업 수행 | 짧은 선택을 여러 번의 대화로 늘릴 수 있음 |
| 자연어 → 편집 가능한 시간표 | 복잡한 반복 입력 축소 | 모호한 말의 확인, 오해 수정, 결과 검토 비용을 포함해야 함 |
| 조정 요청 문구 작성 | 커뮤니케이션 보조 | 핵심 조율 문제를 해결하는 차별점으로는 약함 |

- 비교용 가상 입력: ‘다음 주 월~목 오후 중 한 시간, 화요일은 3시 이후, 점심 직후 제외’. 실제 고객 발화가 아니다.
- 설계 가설: AI가 해석한 범위를 시간표에 보여주고 사람이 수정·확인한다. ‘점심 직후’는 임의 확정하지 않는다. 사람이 확인한 명시적 조건으로 참석 가능 여부를 계산한다.
- 기본 조작 대안: 드래그·직접 입력을 유지하며 AI를 필수 관문으로 만들지 않는다.
- 반증 조건: 입력·모호성 확인·수정·최종 검토까지 합해 기존 방식보다 부담이 커지면 적용하지 않는다. 해석 정확도와 잘못 포함한 시간도 확인한다.
- 산출물: 현재는 이 논의 기록뿐. AI 시안·프로토타입·비교 결과 없음.
- 수록 검토: ‘AI를 넣지 않은 이유’도 판단을 보여줄 수 있으나 지금은 보류 권고 단계다. 나중에 실제 선택과 결과를 보고 수록 여부를 결정한다.

## 후속 이력

- 2026-09-12: 기존 자료와 대화를 연결해 초기 기록 생성. 실제 사용자 검증·AI 개발·포트폴리오 수록 결정은 수행하지 않음.
- 2026-09-12: 사용자가 시간 입력 비교안 구현을 승인. D-006의 재검토를 D-008의 로컬 비교 구현으로 진행. 실제 사용자 효과 판단은 계속 보류.

## D-008 · 시간표 중심안과 범위·예외안의 비교 구현

- 사건·기록일: 2026-09-12. 사후 개선. 사용자 ‘그렇게 해보자’로 제안된 비교안 구현 승인.
- 상태: 비교 구현·기능 검수 완료. 제품 기본안 채택과 포트폴리오 수록은 미정.
- 문제: 긴 시간표와 다수 도구를 해석하는 부담을 줄이면서, 대부분 가능한 사람과 드문 가능 시간을 가진 사람 모두 정확히 입력할 수 있는가?
- 고려한 대안: 기존 시간표 유지(A) / 기본 범위 확인 후 예외 편집과 날짜별 결과(B) / AI 자연어 입력. 이번에는 A·B만 구현·연결했다.
- 중요한 정정: A도 이미 평일 9–18시에서 제외할 수 있었다. 따라서 비교 대상은 기능 유무가 아니라 정보 배치와 입력 순서다. B의 초기 확인 단계는 추가 비용이라는 점도 기록한다.
- 구현: 독립 예시 데이터, 세 과제, B의 빈 범위 시작·직접 입력·되돌리기·시간표 펼치기, 완료 후 초과·누락 판정과 선택적 JSON 기록. 기존 공통 컨트롤과 계산을 재사용.
- 검수 중 수정: 모바일에서 검토 설정이 실제 입력을 밀어내 시작 후 접히게 변경. 320px의 추가·제외 버튼 줄바꿈을 수정. B 기본 범위 확인 전의 조기 완료를 막음.
- [상세 조건·원본 사본·전후 캡처·검증](../design/time-entry-comparison-2026-09-12/README.md). 도메인 52개 테스트, 빌드·린트 통과. 브라우저에서 세 과제의 B 결과 정확성을 확인했다. 터치 기기·스크린리더 전 과정은 미검증.
- 근거 한계: 개발 에이전트 검수이며 인간 사용성 실험은 아니다. 표시된 에이전트 소요 시간은 효과 측정에서 제외하고 관찰 CSV는 채우지 않았다.
- 재검토 조건: B가 빠르더라도 잘못된 시간 포함이 늘면 수정. 모달 왕복과 기본 범위 설정까지 합한 비용으로 비교.
- 기여: 사용자가 입력 마찰·설계 비교와 기록 보존의 우선순위를 정함. 에이전트가 비교 흐름·코드·가상 과제·기능 검수·문서화를 수행. 실제 사용자의 성과 개선은 아직 주장할 수 없음.
- 수록 검토: 기존 안을 유지하며 대안의 이익과 비용을 비교한 과정은 후보. 최종 채택 이유와 실제 관찰 근거를 보강해야 함.

## D-009 · 입력 비교에서 제품의 존재 이유로 초점 복귀

- 사건·기록일: 2026-09-12. 사후 기획 재검토.
- 사용자 피드백: 필요한 것은 실험 진행 도구가 아니라, 경쟁력이 부족한 제품을 어떤 문제 정의와 기획 변경으로 개선하는지 보여주는 과정이다. 직전 비교 화면은 무엇을 위한 것인지 이해하기 어려웠다.
- 판단: 에이전트가 제품 가치의 검토를 국소적인 시간 입력 비교와 실험 도구 구현으로 축소했다. D-008의 계산 검수는 제품 경쟁력의 근거가 아니다. 비교 도구 확장을 중단하고 기존 산출물은 보존한다.
- 제안 상태: 아래 제품 초점은 에이전트의 권고이며 사용자 채택·구현·효과 검증 전이다.
- 권고하는 대상 상황: 같은 회사 동료의 회의에서 첫 후보에 합의하지 못해 주최자가 다시 사람별로 확인해야 하는 순간.
- 문제 가설: 응답 수집 후에도 주최자는 누구에게 어떤 양보나 확인을 요청해야 확정할 수 있는지 직접 재구성해야 한다. 전체 시간표 재입력을 요청하면 이미 확인한 답까지 다시 받게 된다.
- 제품 제안: 확인된 응답을 보존하고, 후보별로 필요한 추가 확인과 이미 알려진 부담을 드러내며, 주최자가 선택한 후보에 필요한 사람의 명시적 확인을 받아 확정으로 연결한다. 미응답·불가·조정 의향·이동 동의를 구분하며 동의는 추정하지 않는다.
- 기존과의 차이: 후보 우선 응답·미확인 모델은 이미 존재한다. 새 이름을 붙이는 것을 피벗이라고 주장하지 않는다. 실패한 첫 조율 → 제한된 재확인 → 답변 반영 → 확정 또는 범위 재탐색이 연결되어야 실질적인 변화다.
- 대안과 비용: 시간 입력 개선은 보조 과제로 보존. 포괄적 AI 추천은 문제와의 연결이 약해 우선하지 않음. 표적 재확인은 반복 연락과 특정인에게 양보가 집중되는 위험이 있으므로 항상 더 낫다고 주장하지 않는다. 후보가 모두 명시적으로 불가능하면 범위를 넓히고, 미확인을 불가능으로 취급하지 않는다.
- 근거: 기존 공개 사례 조사 A2·A3와 경쟁력 검토의 불확실성·동의 구분. 이 자료는 가설을 탐색할 이유이며, 빈도·시장 공백·사용자 효과를 입증하지 않는다.
- 다음 설계 산출물 제안: 합의가 없는 가상 회의 한 건을 현재 방식과 재기획 흐름으로 끝까지 풀어낸 핵심 3장면. 대기·거절·새 후보로 바뀔 때 기존 답의 재사용 범위까지 명시. 도구 구축보다 설계의 차이를 먼저 검토한다.
- 반증 조건: 기존 메신저 확인보다 재질문·해석 부담이 크거나 조정 의향을 동의로 오인하면 수정. 실제 조율 경험에서 이 병목이 중요하지 않으면 대상 상황부터 재검토한다.
- 검증·수록: 이번 변경은 방향과 실패 학습의 기록뿐이며 제품 코드는 변경하지 않음. 포트폴리오 수록 미정. 사용자 문제 제기와 에이전트의 후속 기획 제안을 구분한다.

### D-009 후속 · 조율 복구 시안 구현

- 2026-09-12: 사용자 ‘빠르게 구현해 봐’로 핵심 흐름의 프로토타입 구현 승인. 제품 기본안 채택·효과 입증·포트폴리오 수록 승인은 아님.
- 구현: 필요한 사람의 단일 시간 확인 → 답변 → 주최자 확정. 거절 후 다른 후보 유지·재배치, 응답 대기 취소, 두 후보 모두 거절 시 새 범위 안내. 기존 디자인 시스템을 재사용하고 시간 입력 실험 도구는 보존.
- 검수와 범위: 빌드·린트·도메인 56개 테스트 통과. 브라우저 성공/거절/취소/화면 왕복 확인. 실제 발송·저장·다중 사용자와 새 범위의 재요청은 미연결. [화면·구현·검수·한계](../design/coordination-recovery-2026-09-12/README.md).
- 설계 비용: 동시에 여러 사람에게 일정 변경을 요청하지 않도록 요청을 하나씩 진행한다. 응답 지연 비용을 피할 수 있도록 취소를 제공하지만 실제 효과는 미검증. 향후 늦게 도착한 답과 요청 버전의 처리가 필요하다.
- 기여: 사용자가 기획 변화와 실패 복구를 보여달라는 목적·구현 착수를 결정. 에이전트가 가상 사례·상태 전이·세 장면과 스타일·검수를 구현했다.

## D-010 · 복구 시안의 채용 설득력 재평가

- 2026-09-12, 사용자 요청: 채용자 관점에서 원래보다 좋아졌는지 냉철하게 판단.
- 상태: 비평 기록. 제품 변경·추가 개발·최종 방향 채택 없음.
- 판단: 다음 행동과 동의 의미의 전달은 좋아졌으나, 기존 후보별 추가 요청을 압축한 성격이 강하다. ‘다른 5명은 가능’이라는 유리한 가상 조건과 두 후보 거절 이후의 미연결 때문에 ‘합의 실패 복구’라는 큰 약속을 입증하지 못했다.
- 대안: 마지막 확인이 남은 상황으로 약속을 좁히기 / 공통 가능 시간이 없는 상황의 해결을 끝까지 설계하기. 둘 중 무엇을 채택할지는 미정. 새 화면을 더 늘리는 것을 기본 다음 단계로 삼지 않는다.
- 근거·범위: 현재 시안 4단계의 새 캡처·DOM, 기존 요청 컴포넌트, 이전 설계 기록. [평가와 화면](../research/hiring-review-2026-09-12/review.md). 최초 제출물의 동일 장면, 실제 사용자 성과, 타 지원작은 비교하지 못함.
- 수록 검토: 미정. 독창적인 피벗으로 포장하기보다, 첫 시안이 약속보다 쉬운 문제를 풀고 있다는 발견과 수정 판단을 남긴다.

## D-011 · 공통 시간이 없는 상황의 복구 모델을 중심 방향으로 채택

- 2026-09-12. 사용자가 ‘계산은 제품이 하고, 사회적 판단은 사람이 한다’를 중심 원칙으로 제시하고, 복구 경로와 변경 부담 비교를 실제 사례 하나로 완결하는 것을 우선한다고 명시했다.
- 상태: 제품 방향 채택. 구현·효과 검증·포트폴리오 수록은 별도. D-010의 두 대안 중 공통 시간이 없는 상황의 복구를 선택했다.
- AI: 핵심 추천 기능으로 도입하지 않는다. 보조 문구·요약은 가능성만 보존하며 개발 착수 결정은 없다.
- 구체화: [복구 모델 방향과 단일 사례](../product/recovery-model-direction.md). 미응답과 알려진 충돌을 분리하고, 인원·변경 건수를 사회적 비용 점수로 바꾸지 않는다. 1명 변경 경로가 거절되어 2명 변경 경로를 진행하고 부분 동의·거절·모든 경로 실패까지 다룬다.
- 근거 구분: 제품 철학은 사용자 결정. 세 후보와 분기 사례는 에이전트가 만든 가상 설계 자극이며 실제 고객 사례가 아니다. 사용자 제시 국내 경쟁 제품 분류는 이번에 독립 검증하지 않았고 경쟁사 기능 부재의 근거로 사용하지 않는다.
- 보존: 기존 recovery 시안과 비평은 초기 탐색 기록으로 유지. 이번에는 기준 문서만 변경했으며 제품 코드는 변경하지 않음.

## D-012 · 응답에서 복구 경로를 계산하는 모델 구현

- 2026-09-13. 사용자 구현 승인. 기존 두 후보 시안을 보존하고 별도 계산 모델로 확장.
- 계산: 필수자의 변경 의향·미응답·변경 불가 분리, 사람 수와 변경 일정 건수 분리. 선택 참석자 불참은 필수 조건 실패로 계산하지 않는다.
- 상태: 같은 경로의 여러 사람에게 동시 확인, 부분 동의 후 확정 방지, 거절·취소 후 늦은 응답 무효, 요청별 동의 이력 보존. 새 후보에 기존 답을 전용하지 않는다.
- 범위: 주어진 필수/선택 기준과 후보에서 경로를 도출하는 로컬 모델. 변경 부담의 점수나 사회적 우선순위는 계산하지 않음. 사용성 효과·실제 발송은 미검증. 화면 연결과 검수는 후속 기록.
- 포트폴리오 수록 미정. 가상 사례이며 실제 조율 실험으로 소개하지 않는다.

### D-012 후속 · 화면 연결과 분기 검수

- 2026-09-13: 복구 모델을 개발용 recovery 경로에 연결했다. 기존 초기 시안 소스와 캡처는 보존했다.
- 고정 문구 후보를 확장하는 대신 응답 기반 계산을 채택. 한 후보의 여러 당사자에게 함께 요청하고, 다른 후보와 변경 약속을 중복 추진하지 않는다. 이 운영 방식의 대기 비용은 미검증이다.
- 변경 의향과 동의, 새 후보의 미확인, 거절·취소된 요청 이력을 구분한다. 새 시간 제안부터 재확인과 확정, 확정 없는 종료까지 연결했다.
- 브라우저에서 1명 거절 후 2명 경로, 부분 동의 확정 차단, 전원 동의 확정, 일부 동의 후 거절된 경로의 참석자 안내, 새 후보 재확인·확정, 종료 확인. 모바일 390×844 가로 넘침 없음. 빌드·린트·도메인 60개 테스트 통과.
- [산출물·대안·캡처·검수 한계](../design/constraint-recovery-2026-09-13/README.md). 서비스 본편과 서버·실제 발송은 미연결, 사용자 효과와 포트폴리오 수록은 미정이다.

## D-013 · M1 최초 조정 의향과 변경 동의의 의미 분리

- 2026-09-13 · 사후 개선 · 사용자 ‘그럼 작업해볼까’로 M1 착수 승인. 구현·기능 검수 기록, 사용자 효과 및 포트폴리오 수록 미정.
- 문제: 기존 서비스의 adjustable은 확정되면 옮겨 참석한다는 약속이지만 새 복구 시안에서는 의향으로 해석해 의미가 충돌했다. 코드·문구 대조에서 발견한 문제이며 사용자 연구 결과가 아니다.
- 대안: 기존 값을 일괄 재해석 / 과거 데이터 초기화 / 새 의향값 추가. 기존 의미와 데이터를 보존하기 위해 세 번째를 선택했다. 이전 약속을 편집 화면에 별도 표시하는 복잡성을 감수한다.
- 구현: 새 adjustment_intent, 기존 adjustable/adjustment_commit 보존, 미응답과 분리한 recovery 판정, 의향을 확정 인원에서 제외, 실제 확정 동작 재계산, 후보·범위 입력·완료 요약·주최자 근거 문구 정합화. 일정 상세 미공유를 0건으로 주장하지 않음.
- 검증: 빌드·린트·63개 테스트, 개발용 참석자 응답의 제출 전 안내·완료 UI 확인. 실제 동의 요청의 서비스 연결은 M3, 대표 화면은 M2에서 후속 작업.
- [마일스톤 상태·의미 표·검수 범위](../product/recovery-milestones.md). 기존 제출물·초기 시안 기록과 사용자 보강 기획 문서는 덮어쓰지 않음.

## D-014 · M1 화면디자인 우선으로 순서 정정

- 2026-09-13. 사용자 피드백: 개발 구현보다 화면디자인을 우선한다. M1의 기존 완료는 의미·기능 기반 완료로 한정한다.
- 문제: 최초 입력은 선택 의미를 작은 하단 설명에 의존했고, 확인은 의향만 재질문했으며, 완료는 건수만 보여 날짜별 답을 확인하기 어려웠다. 에이전트의 화면 해석이며 사용자 연구 결과가 아니다.
- 대안: 기존 즉시 제출 유지 / 의향만 확인 / 모든 답을 요약 후 제출. 세 번째를 시안으로 적용. 확인 비용 증가를 감수하며 이해 효과는 검증하지 않았다.
- 결정: 선택 면과 보조 설명, 모바일 전체 너비 조작, 공통 날짜별 응답 목록, 완료의 시간 미확정 상태. 기존 무드보드와 토큰 유지. 도메인·서버 기능 확장은 하지 않음.
- 상태: 화면 시안 작성, 사용자 리뷰 대기. 선택·확인·수정·완료 브라우저 확인. 마일스톤에 디자인과 구현 상태를 분리했다.
- [화면 캡처·검수 범위·남은 판단](../design/m1-screens-2026-09-13/README.md). 포트폴리오 수록 미정. 사용자가 수정한 제품 방향 문서는 보존했다.

### D-014 후속 · 간격·밀도·위계 재조정

- 2026-09-13. 사용자 피드백: 구조 정리만으로 화면디자인을 완료했다고 볼 수 없으며 패딩·밀도·위계·리듬을 더 다뤄야 한다. 적용 승인 후 최초 응답 화면에 집중했다.
- 날짜 입체 배지를 평문 날짜로 바꾸고 시간 크기를 우선했다. 선택 완료 체크와 버튼별 반복 설명을 제거하고 의향 안내를 입력 앞 한 곳으로 이동했다. 카드 간격 12px, 내부 패딩 데스크톱 세로20/가로24px·모바일16px, 버튼 최소44px로 구성했다.
- 기존 카드를 더 장식하는 대안 대신 카드 안 장식과 정보 반복을 줄였다. 흰 표면과 얕은 그림자·파란 선택 면은 유지한다. 긴 후보 목록의 세로 스크롤은 남는다.
- 390px 브라우저에서 세 카드 높이168px·패딩16px·가로 넘침 없음을 확인. 화면 기록 refined-default.png 및 refined-mobile.png. 사용자 이해·미감 평가는 아직 사용자 리뷰 대기, 포트폴리오 수록 미정.

### D-014 후속 · 확인·완료 화면에 간격 기준 확장
