# 시간 선택 입력 검증

최신 상태: 시간 제외 / 시간 추가가 각각 목적이 정해진 입력창을 연다. 입력창 안의 모드 선택과 기본 화면의 누적 시간 집계를 없앴다. 아래 수치 검증은 이전과 동일한 선택 데이터에 대한 기록이며, 최신 UI 검증은 [화면 정리 기록](time-clarity-2026-09-10/review.md)을 참고한다.

| 사용자 상황               | 현재 동작                                          | 브라우저 확인                                                    |
| ------------------------- | -------------------------------------------------- | ---------------------------------------------------------------- |
| 한두 칸만 바꿈            | 같은 칸을 누르면 선택/해제                         | 45시간 → 44시간 30분 → 45시간, 모바일도 동일                     |
| 드래그로 여러 날짜 수정   | 시작 칸의 상태로 사각형 범위를 추가 또는 제외       | 월~수 9–11시 제외: 45→39시간, 역방향 추가: 39→45시간, 되돌리기 한 번씩 39→45시간 |
| 가로로 같은 시간 수정     | 같은 행에서 좌우 드래그                            | 월~금 12–12:30 제외: 45→42시간 30분                              |
| 기간 밖까지 드래그        | 범위에 걸친 회의 기간 밖 날짜는 무시                | 금~일 9–10시 드래그: 금요일만 제외, 45→44시간, 주말 선택 0개     |
| 평일마다 점심은 안 됨     | 직접 입력 → 기본 12–13시 제외                      | 5일의 점심만 제외되어 45시간 → 40시간                            |
| 야간에만 가능             | 옵션에서 비우고 직접 입력으로 추가                 | 19시 이후 입력·시간표 확장, 기간별 집계 확인                     |
| 다른 주 / 주말 / 자정     | 주 이동 후 날짜 선택, 23–24시 추가                 | 다음 주의 평일 5일+토요일에 6시간 추가; 빈 주는 추가 모드로 시작 |
| 키보드 사용               | 방향키·Enter/Space·Ctrl/⌘Z, native select·checkbox | 선택·해제·되돌리기, 입력 모드 방향키 확인                        |
| 입력하다 취소             | Escape 또는 닫기                                   | 저장된 시간 유지, 원래 입력 버튼으로 포커스 복귀                 |
| 입력창에서 Tab 사용       | 마지막↔첫 컨트롤 순환                              | Tab/Shift+Tab 양쪽 확인, 배경 입력은 modal로 차단                |
| 날짜 미선택 / 종료 역전   | 필드 가까이에 오류, 적용 비활성                    | 두 오류와 버튼 비활성 확인                                       |
| 회의보다 짧은 구간만 남김 | 이유 안내, 다음 단계 비활성                        | 1시간 회의에 30분씩 5일은 진행 불가                              |
| 변경을 되돌림             | 최근 20회 복원                                     | 일괄 입력과 드래그를 각각 한 단계로 되돌림                       |

메모리 예시에서 수행했으며 실제 저장 회의·응답·확정은 변경하지 않았다. 320/390px 입력창과 919px 기본 화면의 가로 넘침을 확인했고, 실제 포인터 드래그와 키보드 입력을 사용했다. 날짜 입력 자동화의 fill은 React 상태 반영이 되지 않아 실제 ArrowUp 키 입력으로 기간 변경을 확인했다. 사용자 동작에서 날짜 저장 오류가 확인된 것은 아니다.

도메인 테스트 49개, 빌드, 린트 통과. 원본 불변성, 다른 사람의 데이터 보존, 중복 적용, 주말·자정, 범위 밖·잘못된 입력을 도메인 테스트가 검사한다.

실제 사람을 대상으로 한 사용성 테스트, 실기기 터치, 스크린리더 전체 검증은 수행하지 않았다. 넓은 기간과 자정을 넘는 반복 일정의 입력 편의성까지 검증 완료한 것은 아니다.

검토 페이지의 중복 createRoot도 수정했다. 점심 제외로 40시간인 상태에서 화면 모듈을 갱신해 40시간 유지·검토 화면 한 개·되돌리기 동작을 확인했다.
