# MeetCue 디자인 시스템 — 작업 중

2026-09-10. 코드와 함께 발전시키는 기준이다. 무드보드는 표현의 방향을 제시하며, 정보 구조를 강제하는 명세가 아니다.

## 시각적 기준

- [011 선택 카드](references/2026-09-07/011.png): 위쪽의 밝은 빛, 옅은 파란 선택 면, 명확한 외곽선.
- [005 응답 카드](references/2026-09-07/005.png): 흰 면과 부드러운 깊이, 의미 있는 상태색.
- 배경은 거의 흰색으로 유지한다. 어두운 바탕으로 카드를 띄우지 않는다.
- 주 카드와 후보 카드는 같은 재질이다. 위계는 글자 크기와 여백, 정보 순서로 만든다.
- 상태는 색만으로 표현하지 않는다. 선택 버튼은 `aria-pressed`, 응답에는 상태 문구를 함께 제공한다.

## 사용 예

```tsx
<MainCard material="soft">주요 일정</MainCard>
<MainCard as="article" material="soft" interactive selected={selected}>
  <button type="button" aria-pressed={selected} onClick={onSelect}>
    <CalendarDate compact value={candidate.startAt} />
    <TimeRange start={candidate.startAt} end={candidate.endAt} />
  </button>
</MainCard>
```

`interactive`는 호버 표현만 제공한다. 컨테이너를 가짜 버튼으로 만들지 않고 내부에 실제 button/link를 둔다. `selected`는 의미상 선택된 항목에만 사용한다. 참석 가능/불가와 선택 여부를 혼용하지 않는다. 기존 `MainCard` 호출은 plain으로 유지된다.

## 재질과 상태

`--mc-soft-*` 토큰에서 canvas, fill, border, radius, shadow, selected-fill/border/shadow를 관리한다. 호버는 면과 경계를 조금 강조하고, 포커스는 실제 컨트롤의 포커스 표시로 구별한다. 선택 면은 011번 이미지처럼 옅은 파랑과 외곽선으로 표시한다. 큰 광채와 배경 딤은 사용하지 않는다. 시스템의 움직임 줄이기 설정에서는 선택 전환을 끈다.

참석 가능은 민트, 일정 조정은 살구색, 어려움은 옅은 적색, 미확인은 중립색이다. 브랜드 파랑은 선택/행동을 나타낸다.

## 공간과 글자

관련된 문구 8px, 정보 묶음 20–24px, 데스크톱 주요 면의 안쪽 28px를 출발점으로 삼는다. 모든 간격을 같게 하지 않는다. 후보 시간 16px, 후보 상태·보조 인원 13px, 판단 본문 14px, 결론 20px, 큰 시간 36–52px를 사용한다. 긴 내용이나 좁은 화면에서는 실제 줄바꿈을 보고 조정한다.

## 화면에 적용하는 방식

- **만들기:** 상단 질문 → 조건 요약 → 편집 도구 → 시간표 순서. 반복 안내를 줄인다. 연속 시간은 하나의 범위로 연결하고 시작에 체크를 표시한다. 모바일은 하루씩 누르거나 여러 날짜의 범위를 한 번에 입력한다. 되돌리기는 현재 시간표의 최근 20회 변경을 차례로 복원한다.
- **초대·응답 대기:** 응답 수를 목록 앞에 표시한다. 이름·역할·상태가 먼저 읽히고 개인별 초대 도구는 보조 행동이다. 데스크톱은 같은 행에, 모바일은 펼침 메뉴에 둔다.
- **확정:** 주최자·참석자 모두 `MeetingReceipt` 안에 `MeetingSchedule`을 사용한다. 성공 안내, 회의명·날짜·시간, 다음 행동 순서이며 일정을 다시 큰 카드 안에 가두지 않는다. 큰 시간은 28–42px, 완료 틀 최대 폭은 720px이다.
- **홈·목록:** 응답 필요 → 이어서 작성 → 조율 중의 실제 항목을 앞에 둔다. 조율할 항목이 없으면 확정 일정을 본문에 둔다. 확정된 행에는 지난 응답률·마감을 반복하지 않는다. 빈 요청에서는 완료한 응답으로 이동할 수 있다.

## 적용 범위와 이관 원칙

결과 화면에서 시작한 재질과 날짜 표현을 만들기 틀·조건 입력·시간표, 초대·응답 대기, 참석자 후보 응답, 양쪽 확정, 홈·목록에 확장했다. 공통 MainCard 재질의 `.account-shell` 의존성을 제거했다. `ServiceFoundation.css`의 만들기·초대·확정 재질 덮어쓰기를 줄이고 초대 목록·확정 화면의 구형 CSS를 정리했다.

사이트의 모든 과거 스타일을 제거한 상태는 아니다. 만들기 1·2·4단계의 내부 구성, 참석 기준 편집, 전체 참석자 시간표 등은 기존 구조와 공존한다. 전역 스타일을 일괄 삭제하지 않고 화면을 실제로 이관할 때 해당 규칙을 제거한다.

다음 화면을 수정할 때는 해당 컴포넌트를 실제로 교체한 뒤 기존 재질 규칙을 지운다. 공통 토큰 변경은 일반·선택·호버·키보드 포커스 및 좁은 화면을 함께 확인한다. 화면별 복사본이나 똑같은 역할의 새 카드 컴포넌트를 추가하지 않는다.

## 살아 있는 검토 페이지

개발 서버에서 [화면과 상태 검토](http://127.0.0.1:5173/meetcue/design-review.html)를 연다. `design-review.html` → `src/design-review.tsx` 진입점 → `src/DesignReview.tsx` 검토 화면이 실제 제품 컴포넌트를 호출한다. 실행 코드와 화면의 Fast Refresh 경계를 분리해 중복 createRoot와 수정 시 예시 상태 초기화를 방지한다. 시간 선택·조건 입력·초대 현황·응답 대기·참석자 응답·양쪽 확정·응답 완료·초대 오류의 9개 예시가 있다. 컴포넌트를 수정하면 이 화면도 함께 바뀐다.

예시 데이터는 메모리에만 보관하며 새로고침하면 초기화된다. 모든 제품 기능을 구현한 별도 서비스가 아니라 화면·상태를 비교하는 도구다. 운영 빌드에 추가한 진입점은 없으며 개발 모드에서만 렌더링한다. 실제 홈과 목록은 서비스 화면에서 확인한다.

## 시간 입력의 기준 — 복잡도 재정리

9월 10일에 입력 기능을 확장하면서 진한 모드 선택, 프리셋, 날짜 일괄 선택 도구, 반복 안내가 기본 시간표 위에 쌓였다. 기능 검증과 화면 완성도를 혼동한 변경이었다. 아래 규칙이 그 버전을 대체한다.

- 기본 화면은 목적 → 조건 요약 → 주간 이동·시간 제외/추가·되돌리기·옵션 → 범례·조작 안내 → 시간표 순서다. 같은 내용의 설명과 구분선을 반복하지 않는다.
- 시간표에는 모드 선택이 없다. 선택된 칸은 누르면 제외, 빈 칸은 누르면 추가한다. 데스크톱 드래그는 처음 누른 칸을 기준으로 한 동작을 여러 날짜×시간의 사각형 범위에 적용한다. 방향에 관계없이 같은 범위를 미리 보여주며, 회의 기간 밖 날짜는 제외하고 한 번의 되돌리기로 복원한다. 모바일 탭과 키보드도 같은 선택/해제 규칙을 쓴다.
- **시간 제외 / 시간 추가**는 현재 선택을 변경하는 별도 입력창을 연다. 모드 토글이 아니며 달력의 선택 의미는 항상 후보 시간이다. 입력창에서 모드를 다시 선택하지 않고 날짜·시작·종료만 입력한다. 점심 제외는 기본값 12–13시를 바로 적용할 수 있다. 평일 9–18시의 기본 선택에서는 안 되는 시간만 빼도 된다는 안내를 보여준다.
- 한 번 적용 가능한 범위는 현재 보고 있는 주다. 날짜는 기본 평일 선택이며 주말도 회의 날짜 범위 안이면 개별 선택할 수 있다. 전체 후보가 없으면 제외는 비활성, 추가는 활성이다. 회의 길이로 오해할 수 있는 누적 시간·날짜 집계는 기본 화면에서 제거했다. 한 주에 끝나는 회의는 중복 주간 범위 대신 연월을 표시한다.
- 복원·비우기·24시간 보기는 옵션에 모은다. 되돌리기는 기본 화면에서 계속 접근 가능하며 최근 20회 변경을 복원한다. 범위 입력에서 00:00–24:00를 지원하고 자정을 넘는 범위는 날짜를 나눠 입력한다.
- 총 시간과 별개로 회의 길이를 담을 연속 구간이 있어야 진행한다. 조건을 수정해도 기존 시간 선택을 기본값으로 덮어쓰지 않는다.
- 시간표의 칸마다 작은 카드를 반복하지 않는다. 연속된 선택은 연결된 면으로 보이며 시작에 체크를 표시한다. 제외는 중립색으로 되돌아가고 오류와 혼동시키는 적색을 쓰지 않는다.

### 색의 역할

| 역할               | 공통 토큰 / 표현                                             |
| ------------------ | ------------------------------------------------------------ |
| 본문·보조 문구     | `--mc-color-text-primary/secondary/muted`                    |
| 선택 상태          | `--mc-soft-selected-fill/border`, 체크; 진한 채움 사용 안 함 |
| 시간표의 선택 구간 | `--mc-color-accent-soft`, 공통 선택 테두리                   |
| 주요 실행          | `Button primary`, 현재 작업의 적용 또는 다음 단계            |
| 보조 도구          | `Button secondary/quiet`, 별도 파란색 지정 안 함             |
| 실제 입력 오류     | `--mc-color-danger`, 필드와 오류 문장에만 사용               |
| 입력창             | 밝은 공통 면, 실제 modal을 열었을 때만 scrim 사용            |

`AvailabilityWindowPicker.css`, `TimeRangeEntry.css`, `segmented-control.css`, `dialog.css`에는 독립적인 색상 값을 두지 않는다. 구형 모드·프리셋·범례·안내판 CSS는 제거했다. 검토 페이지의 탭은 중립색 밑줄로 표시해서 제품의 주요 버튼과 경쟁하지 않는다.

## 검증

- `npm run build`, `npm run lint`, `git diff --check` 통과.
- 도메인 테스트 49개 통과. 시간 범위의 다중 날짜 적용·불변성·중복·주말·자정·잘못된 입력을 추가 검증했다.
- 시간표 390/768/1280px, 모바일 초대 메뉴와 확정 화면, 데스크톱 응답 대기·양쪽 확정·초대 오류의 배치를 확인했다.
- 시간표 키보드 선택·되돌리기, 회의 길이 라디오 방향키, 직접 입력 오류·다음 버튼 비활성, 후보 응답·조정 확인 대화상자와 Escape 닫기를 확인했다.
- 실제 홈 → 내 회의 검색/검색 빈 상태 → 받은 요청 → 완료한 응답, 로고의 홈 이동을 확인했다.
- 이전 결과 화면 검토에서 참석 요약 클릭/Enter 펼침·닫힘과 후보 전환을 확인했다.
- 실제 회의의 확정·응답 요청·응답 제출은 실행하지 않았다. 실기기 터치/드래그, 스크린리더와 전체 색 대비 측정은 별도 검증이 필요하다. 전체 접근성 인증을 의미하지 않는다.
