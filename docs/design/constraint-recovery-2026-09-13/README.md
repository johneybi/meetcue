# 응답에서 계산하는 복구 경로

2026-09-13 · 사후 개선 · 로컬 프로토타입 구현 기록. 포트폴리오 수록 미정.

## 문제와 선택

사용자가 채택한 원칙은 ‘계산은 제품이 하고, 사회적 판단은 사람이 한다’이다. 이전 시안은 한 사람의 마지막 확인을 받는 상황에 가까웠다. 이번에는 전원 응답 후에도 공통 시간이 없는 가상 사례를 사용한다. 실제 고객 조율 기록이나 사용자 연구가 아니다.

고정된 후보 설명을 늘리는 대안 대신, 참석자·필수 여부·후보별 응답에서 필요한 변경과 미확인을 계산하는 모델을 선택했다. 변경 인원과 일정 건수는 조건 수이며 사회적 비용 점수나 추천 순위가 아니다. 여러 후보를 동시에 추진하는 대신 한 후보 안에서 필요한 사람들에게 함께 확인한다. 대기 시간이 늘어날 가능성은 미검증이다.

## 연결한 흐름

- 화요일: 민수 1명 / 기존 일정 1건 변경 동의가 필요하다.
- 목요일: 수진·서연 2명 / 각 1건 변경 동의가 필요하다.
- 금요일: 필수 참석자의 변경 불가 외근으로 요청할 수 없다.
- 화요일 거절 → 목요일 요청 → 수진만 동의하면 확정 불가 → 서연까지 동의하면 주최자가 확정.
- 일부 동의 후 거절되면 이전 동의자에게도 진행하지 않는 후보로 표시한다. 이미 보낸 답은 이력에 남는다.
- 새 시간은 주최자가 자신의 참석을 확인하고 추가한다. 다른 사람의 기존 답은 복사하지 않는다. 필수 3명의 새 참석 확인 후 확정할 수 있고 선택 2명의 미확인은 별도로 남는다.
- 모든 경로가 막혀도 새 시간 제안 또는 확정 없는 종료로 이어진다. 취소·거절된 요청의 늦은 답은 요청 ID에 묶여 무효 처리한다.

공유 Button, MainCard, Badge, Avatar, CalendarDate, TimeRange, Dialog와 기존 밝은 재질을 재사용했다. 새 장식 색이나 최적 후보 강조를 도입하지 않았다. 새 컴포넌트는 `ConstraintRecovery`, 이전 `CoordinationRecovery`는 초기 시안으로 보존한다.

## 검증과 캡처

- 경로: `http://127.0.0.1:5173/meetcue/design-review.html?view=recovery`
- 날짜: 2026-09-13. 초기 후보는 실행일 기준 다음 주이며 이번 검증은 9/15·9/17·9/18, 추가 후보는 9/22 14시이다.
- 데스크톱 기본 브라우저 화면에서 초기 비교, 요청 확인, 거절 후 다음 경로, 부분 동의 확정 차단, 전원 동의 후 확정을 UI로 확인했다.
- 부분 동의 후 다른 사람이 거절한 경우, 먼저 동의한 수진에게 종료 안내와 이전 동의 기록이 보이고 입력은 없음을 확인했다.
- 모든 원래 경로 거절 뒤 새 시간 제안 폼 진입을 확인했다. 별도 초기화한 시나리오에서 새 시간 추가 → 필수 3명 참석 확인 → 확정까지 확인했다.
- native 날짜 필드의 자동 `fill`은 표시 값만 바꾸고 React 입력 이벤트를 반영하지 않는 현상이 있었다. 실제 ArrowUp/ArrowDown 키 입력으로 날짜가 반영되어 추가·후속 요청이 정상 동작함을 확인했다. 일반 사용자 입력 실패로 단정하지 않는다.
- 390×844 뷰포트에서 후보 세로 배치와 가로 넘침 없음 확인. 임시 뷰포트는 검증 후 해제했다.
- 조율 종료 확인 대화상자와 종료 화면 확인.
- `npm run build`, `npm run lint`, 도메인 테스트 60개 통과. 요청 버전, 부분 동의, 거절, 취소, 새 후보의 답 분리를 테스트한다.

캡처: [부분 동의](partial-consent.png), [확정](confirmed.png), [모바일 후보](mobile-candidates.png). 데스크톱 full-page 캡처에는 브라우저 캡처 도구의 축소·빈 여백 현상이 있어 원본 그대로 보존했다. 정밀한 시각 비교용으로 사용하지 않는다. 모바일 캡처는 스크롤된 후보 영역이며 전체 화면이 아니다. 일부 문구는 캡처 이후 ‘변경 요청 거절’에서 ‘확인 요청 거절’로 정리했다. 최초 제출물과의 동일 조건 전후 비교는 아니다.

## 남은 한계와 포트폴리오 판단

개발용 검토 경로이며 서비스 본편·프로덕션 빌드 진입점에는 아직 연결하지 않았다. 새로고침하면 상태가 초기화되며 실제 알림·서버 저장·다중 사용자·캘린더 변경은 없다. 추가 후보는 이번 사례의 1시간 회의에 한정한다. 선택 참석자에게 새 요청을 보내는 흐름, 실제 일정 제약의 수집, 조건 변경에 따른 응답 유효기간은 후속 설계 대상이다.

보여줄 수 있는 것은 실패한 후보 이후에도 동의의 범위와 필수 조건을 보존하도록 설계한 판단과 작동하는 분기다. 조율 시간 감소·경쟁 우위·시장 독창성은 입증하지 않았다. 실제 실패 조율 사례와 주최자·참석자의 이해 확인이 추가로 필요하다. 사용자가 문제 초점·설계 원칙·진행을 결정했고, 에이전트가 가상 사례 계산 모델·화면·테스트를 구현했다.
